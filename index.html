How it works

Capture, route, deliver — in the right order

A change-data-capture pipeline that never rewrites your applications and never scrapes whole tables.

01

Capture

Every insert, update and delete is picked up as it commits. It reads from the change stream — log-based or trigger-based, whichever fits — not by scraping whole tables, and never rewrites your applications.

✓ Source systems keep running, untouched
02

Route

Rules decide what goes where. Data is subset, filtered and transformed in flight, so each target receives exactly the shape it needs — down to the table, column, row and direction.

✓ Each target gets exactly the data it needs
03

Deliver

Changes arrive asynchronously, batched and compressed, and are applied in correct transactional order — with automatic retry if the network drops, so delivery resumes where it stopped.

✓ Correct order, nothing dropped
